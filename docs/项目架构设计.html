表格检索 / 模板改造 / 数据核对 Web 应用 —— 需求整合与项目架构

  • 版本：v1.0（需求整合稿）
  • 日期：2026-11-09
  • 样本：samples/项目台账统计表.xlsx（用户提供样板，58 列 / 两级合并表头）
  • 素材实测：微信接收目录 ...\msg\file 下共 65 个表格文件、29.3 MB，格式分布 .xls 32 / .xlsx 30 / .csv 1 / .et 2

一、需求整合

1.1 业务背景

用户日常在两套数据之间工作：

数据 特征
项目台账统计表（模板） 单表 58 列，两级合并表头（2~3 行），含"小计"行、公式与数组公式，是唯一的"标准形态"
各类过程表（来源） 12345 工单导出、扣分明细、超期预警、固定资产台账等，来自系统导出或人工填报，列名/顺序/表头层级各不相同，且 .xls 占一半以上

痛点：要在几十个表格里找一个数/一个合同号，只能逐个打开；来源表要汇总进台账，全靠手工复制粘贴；两个版本核对差异，靠肉眼比对。

1.2 需求条目（原始表述 → 可验收需求）

编号 用户原话 转化后的需求 验收口径
R1 "针对目标文件夹内的所有表格（excel 支持的所有类型）要做全字段模糊搜索" 递归扫描指定文件夹，对每个工作表、每个单元格建立可检索文本；支持关键词/多关键词/短语模糊匹配；结果定位到"文件—工作表—行—列（字段名）"；关键词高亮；结果可导出 语料中任一单元格的可见内容 100% 可被搜到；单元测试 + 抽样人工验证
R2 "表格样式的转换（字段映射）"；补充："模板要求可以替换，但映射内容行列需要可以自行选择调整，也就是说有需要把 A 表某行经转换填写入 B 表某列的可能" ① 模板可替换：任意 xlsx 都能登记为模板（框选"目标数据起始单元格"即可），不写死台账那 58 列；② 映射以坐标为单位：源（行, 列）→ 目标（行, 列）均可自由指定，记录行可自动下移、固定行可写常量；③ 方向不止列→列：列→列、行→列（转置）、列→行、单元格→单元格、区域块→区域块都支持；④ 自动推荐 + 人工调整 + 方案保存复用；⑤ 输出保留模板原有样式/合并/列宽/公式 ①换任意模板也能用；②"A 表第 3 行（横向的字段名→值）→ B 表第 F 列（竖向排列）"能正确生成；③输出在 WPS 打开无修复提示、样式一致；④转置/区域映射提供逐单元格预览
R3 "两表格对应条目的数据对比" 选取两张表（可为不同文件/工作表），指定主键（自动推荐唯一列），按主键匹配条目；输出 新增 / 删除 / 修改 三类差异，字段级逐项展示；每条差异也必须带坐标（左/右两侧各自的文件地址、工作表、第几行、第几列/A1）；可导出带标注的对比报告 对同一台账的两个版本，差异结果与人工核对一致；主键重复/缺失有明确提示而非静默错配；任取一条差异，能直接定位到左右两侧各自的文件与行列
R4 "小体积有简单的图形操作界面可以为 web 应用" 本地一键启动，浏览器打开即用；中文界面；五个功能页签；无需安装 Node/数据库 双击启动脚本 → 自动打开浏览器 → 页面可用；代码总量 < 1 MB；零第三方依赖
R5 "给出的结果需要为文件地址、第几行第几列" 每条命中必须是一份可复现的坐标：文件绝对路径 + 工作表名 + Excel 行号（与左侧行标一致，从 1 起）+ 列字母与列序号（如 AF / 第 32 列）+ A1 引用（AF12）+ 该列表头字段名；并支持一键"打开所在文件夹 / 用 WPS 打开该文件" 任取一条结果，不看界面也能定位到"哪个文件、哪个表、第几行第几列、哪个字段"；界面、导出文件、审计日志三处的坐标口径完全一致
R6 "且可以通过应用进行修改" 在检索结果、预览表、单元格详情中直接编辑并写回原文件；写前自动备份、支持撤销；文件被外部程序改过时保存前做冲突检测；每次修改留审计日志（时间/文件/坐标/旧值/新值）；合并单元格只写左上角、公式格区分"改公式"与"改显示值" 修改后 WPS/Excel 打开无"修复"提示；未涉及的工作表、样式、公式保持不变；备份可一键还原；被外部改动时有明确告警而非静默覆盖

1.3 隐含需求（从样本数据反推，用户未明说但必须做）

编号 事实（实测） 对系统的要求
N1 台账表头是 2 行 × 58 列、22 处合并（如 H2:W2=计划部前期相关资料，其下 16 个子列） 表头识别必须支持多级合并，字段名要拼成路径："计划部前期相关资料 / 项目决策时间"
N2 表中存在 小计行（第 8 行 B8=小计，含 SUM(AC4:INDEX(AC:AC,ROW()-1)) 等公式），第 9~11 行还只是"分类占位行" 检索需覆盖，但字段映射/对比/汇总必须排除小计与占位行，否则数据翻倍
N3 同一项目跨多行（第 4~7 行属同一"示例双创"项目），项目名只在首行出现（视觉靠合并） 对比/映射时需支持"向下填充"类合并语义的补全策略，否则主键匹配会漏
N4 单元格类型混杂：手机号存成数字 13800000003、日期存成文本 2024.3.9、税率存成小数 0.06 显示为 6%、AV 列是数组公式 归一化层要按"目标字段类型"做转换；浮点/科学计数绝对不能当文本搜
N5 一个目录里同名文件带 (1) 副本（如 示例预警.xls、示例台账-修改.xlsx 成对出现） 检索结果要能区分文件版本（显示修改时间），对比功能正好用于核对这种"改前/改后"
N6 .xls 是 OLE2/BIFF8 老格式（实测魔数 d0cf11e0），.et 两种都有（一个 zip、一个 OLE2） 按文件魔数识别格式，不按扩展名；.xls 必须原生可读
N7 目标机 无网络、无 xlrd、无 LibreOffice（实测 pip 不可用） 不能引入任何需要联网安装的依赖；解析器自研
N8 最大单文件 9.4 MB（示例台账.xlsx），总语料 29 MB 读取用流式解析，索引常驻内存可控在 ~200 MB 内
N9 写回比读取危险一个数量级：一个格子可能落在 <c> 节点 + 共享字符串 + 样式索引三处；合并区只有左上角存值；公式格有"公式"和"缓存值"两套内容 写回层必须走"定位原始节点 → 最小改动"路线，禁止整表重写；每次写前备份，写后自检（重开校验）
N10 台账模板只是当前样板：业务上年度/口径变了模板就会换，"58 字段"不能写死在代码里 模板必须可登记、可替换：字段列表与"目标数据起始单元格"由模板解析 + 用户框选，映射方案与模板解耦
N11 "A 表某行 → B 表某列"说明映射不是字段一对一：横向排列的"字段名—值"要变成纵向排列，甚至整块区域互换方向 映射模型必须支持方向与区域：列→列、行→列（转置）、列→行、单元格→单元格、区域块→区域块；否则这类表只能回 Excel 手工做

1.4 非功能需求

项 指标
部署 Windows 10/11 单机；仅需 Python 3.10+；启动.bat 一键运行；监听 127.0.0.1，不对外网开放
体积 应用代码 < 1 MB；第三方依赖 0 个；不打包 Python 运行时
性能 65 文件/29 MB 语料首次索引 < 60 s；增量刷新按 mtime 跳过；单次搜索 p95 < 300 ms；打开 9 MB 工作簿预览 < 3 s；单单元格写回 < 300 ms
数据安全 读取一律只读；写回前必须备份到 data/backup/{时间戳}/，原件可一键还原；写后校验文件可被重新解析；审计日志不可静默丢弃
并发安全 写回前比对 (大小, 修改时间)，与索引时不一致则拒绝并提示"文件已被外部修改"
兼容 读取：xlsx / xlsm / xlsb / xls / csv / et（按魔数）；输出与写回：xlsx / xlsm / et(zip) 原地写回；xls / et(OLE2) 一期另存 xlsx 副本（见 D10）
可维护 层间只依赖数据模型契约；每个解析器有独立单测；新增格式只需实现一个适配器

2.2 关键设计决策

决策 方案 理由
D1 零第三方依赖 只用 Python 标准库（http.server / json / sqlite3 / zipfile / xml.etree / struct / difflib / unicodedata） 目标机无网络，pip 实测不可用；"小体积"要求
D2 自研 .xls 解析 biff.py：CFB(OLE2) 容器 + BIFF8 记录（SST/LABELSST/NUMBER/RK/MULRK/FORMULA/LABEL/MERGEDCELLS） 语料中 .xls 占 32/65，是硬需求。**可行性已用 scripts/probe_xls.py 实测验证**：3 个真实 .xls 全部读出工作表名、字符串、数字、合并区
D3 按魔数识别格式 读前 8 字节：d0cf11e0→OLE2（xls/部分 et）、504b0304→zip（xlsx/xlsm/xlsb/部分 et）、否则按 csv 嗅探编码 .et 实测两种容器都有；扩展名会骗人，魔数不会
D4 模板改造=克隆注入，而非重绘 把模板 .xlsx 当 zip 打开，定位目标 sheet XML，在数据起始行处克隆行节点并写入数据/共享字符串，保留样式索引、合并区、列宽、公式；行样式复用模板"数据样板行" 只有这样才能"样式保真"；自绘样式必然走样。比引入 openpyxl 更可控且零依赖
D5 多级表头识别 从顶部向下扫描：连续非空行且下方为数据 → 判定表头区；用合并区把"跨列标题"向下传播，字段名 = 各级标题用 / 连接；数据区从第一个"类型突变"行开始 台账 2 行 58 列、22 处合并是典型；写死行列号不可维护
D6 索引：字符二元组 + 片段校验 归一化文本 → 中文按 2-gram、英文数字按整词/前缀建倒排；查询先取候选集再逐条做子串校验与打分 中文没有空格分词，2-gram 召回高、结构简单；语料仅 29 MB，内存索引足够
D7 输出只写 xlsx 无论来源是 xls/csv/et，输出统一为 xlsx 统一保真路径；不冒险回写老格式
D8 对比用"主键匹配 + 字段级差异" 主键自动推荐（唯一性/非空率打分）+ 人工指定（支持多列组合）；差异分 新增/删除/修改；文本先归一化再比，数值带容差 真实数据主键常脏（空值、重复、带空格），必须有显式告警
D9 坐标只有一个口径 全局唯一 CellRef = {filePath(绝对), sheet, row(1 起), col(1 起), colLetter, a1, fieldName}，检索结果、导出、审计日志、写回请求全部复用 杜绝"行号从 0 开始 / 行号跳表头"这类事故；用户看到的就是 Excel 左侧行标
D10 写回分层，风险隔离 一期：xlsx / xlsm / et(zip) 原地写回（zip 条目级替换目标 XML 节点，其余条目字节不变）；xls / et(OLE2) 另存为 xlsx 副本（原件保留并备份，界面明确提示"已生成 xlsx 版"）。二期再评估 BIFF8 原地写回（需重排 BOUNDSHEET 偏移，风险高） 不改老格式 = 不冒毁文件风险；绝大多数可编辑需求已被 xlsx/xlsm 覆盖，而 xls 多为系统导出、本就不该回写
D11 写回必须先备份、后自检 写前把原文件复制到 data/backup/{时间戳}/，写后重新解析一遍自检（能读出、目标格 = 新值、工作表数不变），失败则自动回滚 写回是不可逆操作，宁可失败也不能产出打不开的文件
D12 映射模型=规则列表，双模式并存 一条规则 = {source:{sheet,rowSel,colSel}, target:{sheet,rowSel,colSel}, mode, transform}；mode ∈ {cell 逐格, block 区域块, transpose 区域转置, filldown 合并填充, repeat 常量重复}；rowSel/colSel ∈ {fixed:N, record:偏移, header:字段名, span:N}。默认模式①字段映射（列→列，记录逐条下移）覆盖 90% 场景；模式②区域映射（自由框选源/目标区间 + 转置）覆盖"A 表某行→B 表某列"。两种规则可在同一方案里按序混用 用一套坐标化规则同时满足"简单映射"和"异形映射"，避免为转置单开一条代码路径；规则 JSON 可预览、可复用、可手改
D13 模板登记、可替换 模板以"登记"方式管理：{name, filePath, sheet, titleRange, headerRange, dataStartCell, fields[]}，其中 dataStartCell 由用户在预览网格上框选；替换模板=换文件重新解析，映射方案只引用"目标字段名/目标坐标"，不引用具体文件 满足"模板要求可以替换"；年度换模板时旧方案仍可用（字段名映射），无需重做

2.3 统一数据模型（契约，app/core/model.py）

@dataclass
class Cell:            # 一个单元格
    raw: Any           # 原始值
    kind: str          # 'text' | 'number' | 'date' | 'bool' | 'formula' | 'blank'
    text: str          # 展示/检索文本（已归一化前的展示态）
    num: float | None
    formula: str | None

@dataclass
class SheetModel:      # 一个工作表
    name: str
    n_rows: int
    n_cols: int
    cells: dict[tuple[int, int], Cell]
    merges: list[tuple[int,int,int,int]]      # r1,r2,c1,c2
    hidden: bool = False

@dataclass
class WorkbookModel:
    path: str
    fmt: str           # 'xlsx'|'xls'|'csv'|'et-zip'|'et-ole'
    sheets: list[SheetModel]

@dataclass
class Field:           # 识别出的字段
    index: int
    name: str          # '计划部前期相关资料 / 项目决策时间'
    level: int         # 表头层数
    kind_hint: str     # 推断类型：text/number/date/phone/code/money
    col_span: tuple[int,int]

@dataclass
class TableModel:      # 规范化后的"逻辑表"
    source: FileRef
    sheet: str
    header_rows: list[int]
    data_start: int
    data_end: int
    excluded_rows: list[tuple[int,str]]   # [(行号,'小计'|'占位'|'空行')]
    fields: list[Field]
    rows: list[dict[int, Cell]]           # 行号 → {列号: Cell}
    parse_notes: list[str]

@dataclass
class CellRef:          # ★全局唯一坐标（D9），前端/导出/日志/写回共用
    file_path: str      # 绝对路径
    sheet: str
    row: int            # 1 起，与 Excel 左侧行标一致
    col: int            # 1 起
    # 派生属性：col_letter -> 'AF'；a1 -> 'AF12'
    # 展示串：'第12行 · 第AF列(第32列) · AF12'

@dataclass
class EditOp:           # 一次写回请求
    ref: CellRef
    new_value: str | float | None
    kind: str           # 'value' | 'formula' | 'clear'
    expect_mtime: float # 冲突检测用
    expect_size: int

@dataclass
class AuditEntry:       # 审计日志，追加写 data/audit/*.jsonl
    ts: str
    ref: CellRef
    old_value: str
    new_value: str
    backup_path: str
    result: str         # 'ok' | 'conflict' | 'rolled_back'

@dataclass
class TemplateDef:      # 模板登记（D13）：模板可替换，字段/起始格从文件解析
    id: str
    name: str
    file_path: str
    sheet: str
    title_range: tuple[int,int,int,int] | None   # 大标题区（可为空）
    header_range: tuple[int,int,int,int]          # 表头区（支持多级合并）
    data_start: tuple[int,int]                    # ★用户框选的数据起始单元格 (行,列)
    fields: list[Field]

@dataclass
class Sel:              # 行/列选择器（D12）
    kind: str           # 'fixed' 固定N | 'record' 当前记录行+偏移 | 'header' 按字段名 | 'span' 连续N个
    value: int | str

@dataclass
class MappingRule:      # 一条坐标化映射规则
    source: dict        # {sheet, row: Sel, col: Sel}
    target: dict        # {sheet, row: Sel, col: Sel}
    mode: str           # 'cell' | 'block' | 'transpose' | 'filldown' | 'repeat'
    transform: str      # 'identity' | 'number' | 'date' | 'concat' | 'constant'
    on_missing: str     # 'blank' | 'skip' | 'error'

@dataclass
class MappingProfile:   # 映射方案，存 data/profiles/*.json，可复用
    id: str
    name: str
    template_id: str
    source_signature: str      # 来源表头指纹 → 同类表自动套用

    notes: str

2.6 关键技术流程

① 检索：扫描 → 嗅探 → 解析 → 识别表头/数据区 → 每单元格归一化 → 建倒排（token→posting）→ 查询（2-gram 候选 + 子串校验 + 字段权重打分）→ 每条命中带 CellRef（文件绝对路径 + 工作表 + 第几行 + 第几列列号/列字母 + A1）+ 字段名 + 高亮区间。索引按 (路径, 大小, mtime) 判脏，只重建变动文件。

② 模板登记与字段映射：

登记模板（任意 xlsx）→ 解析表头（支持多级合并）得到字段列表
                    → 用户在预览网格上框选「数据起始单元格」→ TemplateDef 落库
选择来源表 → 解析来源字段 → /api/mapping/suggest 自动推荐（名称/别名词典/类型/相似度）
           → 用户在「映射矩阵」里调整：源行/源列 → 目标行/目标列（可固定、可随记录、可按字段名、可跨区域）
           → /api/mapping/preview 逐单元格预演 → 确认 → 保存 MappingProfile
再次遇到同类表：按表头指纹（source_signature）自动套用已有方案

映射两种模式（D12）：

  • 模式①字段映射（默认）：源列 C → 目标列 AF，记录逐条向下平移；覆盖"列→列"绝大多数场景。
  • 模式②区域映射：自由框选源区间与目标区间，可选 transpose（转置）、filldown（合并向下填充）、repeat（常量整列）、block（整块搬运）。"把 A 表某行（横向的字段名→值）填写到 B 表某列（竖向）"就走这条：源区间 A表!B3:AF3 → 目标区间 B表!F4:F37，mode=transpose。
  • 两种规则可在同一方案里按顺序混用；规则全部是坐标化 JSON，可预览、可手改、可复用。

③ 模板生成：打开目标模板 zip → 解析 xl/worksheets/sheetN.xml、sharedStrings.xml、styles.xml → 从 TemplateDef.data_start 起按"数据样板行"样式克隆行节点 N 次 → 按规则列表逐单元格写入（字符串进 sharedStrings，数值/日期按原格 style 的 numFmt 写；区域转置按矩阵坐标映射）→ 更新 <dimension>、删除 calcChain → 其余条目字节原样复制 → 重新打包 → 输出 data/output/台账_YYYYMMDD_HHMM.xlsx。

④ 对比：两张表 → 各取主键列 → 匹配（唯一命中/重复/仅左/仅右）→ 对匹配上的行逐字段比较（归一化后比；数值容差；空值按规则）→ 输出差异矩阵 + 汇总统计，**每条差异同时给出左侧与右侧的 CellRef** → 导出 xlsx（修改单元格黄、仅左红、仅右绿；报告含"左侧文件/行/列、右侧文件/行/列"四列）。

⑤ 编辑写回（R6）：

用户点命中 → GET /api/cell 取单元格详情（值/类型/公式/合并归属/字段名）
        ↓ 在弹窗里改值
PUT /api/cell {ref, newValue, expectMtime, expectSize}
        ↓
① 冲突检测：磁盘 mtime/size ≠ 索引记录 → 409，要求刷新后重试
② 备份：复制原文件到 data/backup/{ts}/<相对路径>
③ 定位：zip 内找到目标 sheet 的 XML，定位 <c r="AF12"> 节点
   - 文本：写 sharedStrings 或内联串，改 t="s"/t="inlineStr"
   - 数值/日期：改 <v>，样式索引沿用原格（不重建样式）
   - 公式：kind='formula' 时改 <f>；kind='value' 时改缓存 <v>
   - 合并区：只允许写左上角，其余坐标拒绝并提示
④ 落盘：其余 zip 条目按原始字节复制；写临时文件成功后原子替换
⑤ 自检：重新解析，校验目标格==新值、工作表数/尺寸未变；失败自动回滚
⑥ 审计：append data/audit/*.jsonl（时间/坐标/旧值/新值/备份路径/结果）
⑦ 增量更新索引中该单元格的 posting

2.7 前端设计（小体积）

  • 单 index.html + 5 个 JS 模块 + 1 个 CSS，无框架、无构建、无 CDN（离线可用）。
  • 页面：检索（文件夹、索引状态、搜索框、结果表、导出）、映射（模板登记/替换、来源与目标网格预览、映射矩阵、区域框选、预演）、转换（选来源+方案→预览前 5 行→生成下载）、对比（左右表选择、主键建议、差异表、导出）、设置（目录、忽略规则、缓存清理）。
  • 检索结果表固定列：文件地址（悬停显示完整路径，可"打开所在文件夹"/"用 WPS 打开"）｜工作表｜第几行｜第几列（字母+序号）｜A1｜字段名｜命中内容（高亮）｜操作（编辑）。
  • 映射页交互（R2）：左侧来源表网格、右侧目标模板网格，两侧都能直接框选单元格/区域；中间是"映射矩阵"（每行一条规则：源行选择 + 源列选择 → 目标行选择 + 目标列选择 + 模式 + 转换）；默认给"字段映射"简表，点"高级/区域"切到转置等模式；右下角"预演"显示逐单元格结果。
  • 对比结果表固定列：差异类型｜主键值｜字段名｜左值｜左文件｜左行/列/A1｜右值｜右文件｜右行/列/A1｜导出。
  • 编辑交互：点行 → 右侧/弹窗显示单元格详情（当前值、类型、公式、合并归属、所属行是否小计）→ 改值 → 保存 → 就地刷新该行与索引；支持"查找替换"页：先列出 N 条"旧值→新值"预演清单，逐条勾选后批量写回。
  • 数据量控制：结果分页（50/页）；预览只取前 50 行；大表用虚拟滚动。

2.8 风险与对策

风险 影响 对策
BIFF 边界情况（BIFF5/加密/异常记录） .xls 解析失败 记录级容错（未知记录跳过）；加密文件标记"需人工另存"；不做激进猜测
表头识别误判（无表头/多行标题/首行空） 映射和对比错位 多策略投票 + UI 可手动调整表头行/数据起始行；parse_notes 暴露判据
模板克隆破坏样式 输出文件打开报修复 只改必要节点（行、共享字符串、dimension），其余字节原样保留；输出后用 WPS 实测打开
合并单元格导致主键缺失 对比大量误判"仅左/仅右" 提供"向下填充"补全开关，默认开启并在结果里标注
中文模糊搜索噪声 结果过多/漏检 默认 AND 多词；短语用引号；后续可选加拼音首字母（v1.1，不阻塞 v1）
真实表格越用越多 索引膨胀 增量索引 + 文件级跳过 + 缓存重建入口
写回毁文件（改错节点/字符串表/样式索引） 文件打不开或数据错乱 最小改动 + 写前备份 + 写后重解析自检 + 自动回滚；只允许写单值/公式，不重排结构
文件被 WPS 打开时写回 写回被覆盖或冲突 冲突检测（mtime/size）；提示"请先关闭该文件"；不强行写只读/被占用文件
误改关键列 业务数据损坏 界面标注主键/金额等敏感列，修改需二次确认；审计日志支持按文件回看与回滚
.xls 无法原地写回 用户以为改了实际没改 明确提示"已生成 xlsx 副本，原件保留"；副本路径与原件路径都显示（见 D10）
转置/区域映射配错 数据错位而不报错（最危险） 强制"预演"：生成前展示逐单元格"来源坐标→目标坐标→值"清单；规则落库后可回看；生成时记录映射 provenance
模板被替换后旧方案失效 用户以为套用了旧方案 方案与模板解耦（按字段名/坐标引用）；模板变更时校验字段是否仍存在，缺失项在 UI 标红并阻断生成

开发需求评估与"切片"方案

  • 版本：v1.0
  • 关联文档：docs/01-需求整合与项目架构.md
  • 结论先行：需要切片，建议切成 5 个开发切片 + 1 个契约/收口阶段（Lead）。切片以"文件写作用域互不重叠 + 只依赖冻结契约"为边界，可在同一工作区并行推进。

一、评估方法

  1. 先落需求与架构（已完成），把系统拆成 6 个可独立验收的能力域；
  2. 对每个能力域估算代码量、耦合度、不确定性（见 2.1）；
  3. 用"能否在契约冻结后独立开工、且改动的文件不重叠"作为可切片判据；
  4. 不可切的部分（契约、骨架、集成、真机验证）留给 Lead 串行完成。

代码量按实现复杂度估算（含注释与必要容错），不含测试脚本。

1.2 已消除的最大不确定性（探针结论）

scripts/probe_xls.py 用纯标准库（struct）实现了 CFB + BIFF8 读取，已在 3 个真实 .xls 上跑通：

  • 示例预警.xls：2 个表，600 单元格，115 条共享字符串，数字/文本/日期混排 ✓
  • 11月2日…工单4件(1).xls：45 单元格 ✓
  • 示例表格C.xls：161 单元格，7 列 ✓

同时实测确认：.et 有两种容器（一个 zip、一个 OLE2），所以必须按魔数而非扩展名分流；目标机无网络、无 xlrd、无 LibreOffice，因此"零依赖自研解析"是唯一可行路线。→ 切片 A 的主要风险已从"能不能做"降为"边界覆盖多少"。

二、切片结论

需要切片。 判据：

  1. 体量：6k+ 行、6 个能力域，单 Agent 串行执行上下文与时间成本都高；
  2. 耦合：A→B→{C,D,E} 是单向依赖，配合冻结契约即可并行；F 只依赖 API 契约，可与后端同时开工；
  3. 冲突面：每个切片改动的目录完全不同（见 4.3 写作用域），天然适合同工作区并行；
  4. 但 G（契约/骨架/集成）与 A+B 强耦合于真实样本，不能切，需要 Lead 先冻结契约并亲自收口。

为什么不是 3 片：3 片会让 D（最重、最不确定）独占一片且无人并行分担，P1 阶段其他片空转。为什么不是 8 片：再拆就要把 A 的 OOXML/BIFF 分给两人，但两者共用 model.py 且都要在同一批样本上联调，沟通成本高于收益；F 再拆会共享同一份 app.js，产生写冲突。

2.3 写作用域与冲突规避

  • 每个切片只写自己表内的目录；app/core/model.py、app/core/cellref.py、app/server.py、app/api.py 只有 Lead 能改；
  • 若某切片确实需要改契约：先在群内提出，由 Lead 改并广播新版本号（CONTRACT_VERSION），不允许各自偷偷加字段；
  • app/web/index.html 由 S0 定骨架，S6 只能改 app/web/pages/*、app/web/app.js、style.css；
  • **写回（S8）只动自己的 writers/、audit.py、edit_service.py**，不得触碰 readers/；S4 只动 template.py/mapping.py/xlsx_writer.py，两者互不越界；
  • 测试文件按域分目录：tests/test_readers_*、tests/test_detect_*、tests/test_search_*、tests/test_convert_*、tests/test_compare_*、tests/test_edit_*，不共享测试文件。

五、切片决策记录（TL;DR）

  • 要切：体量 7k+ 行、7 个单向依赖的能力域、写作用域天然不重叠；
  • 切 6 个开发切片：S1 采集、S2 识别、S3 检索、S4 映射与模板（含转置）、S5 对比、S8 编辑写回，加 S6 前端，共 7 个开发切片，外加 Lead 的 S0 契约与 S7 收口；
  • 先冻契约再并行：model.py（含 CellRef/TemplateDef/MappingRule/EditOp）+ JSON API 是唯一同步点，冻结前不开工；
  • 不切的：契约、骨架、A+B 联调、端到端验收、打包 —— 全部由 Lead 串行兜住；
  • 最大剩余风险在 S4（样式保真 + 转置语义）、S8（写坏文件不可逆）与 S2（表头判据）：S4/S8 在 P1 各先跑"模板包结构探路"和"单格写回探路"，S2 在 P1 用 fixture 先行，把风险前移。
