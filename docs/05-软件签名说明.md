# 软件签名（Code Signing）：怎么签、签哪种

> 适用：`dist/表格工具/表格工具.exe` 及以后的安装包。目标是把"未知发布者"变成可信发布者，减少 SmartScreen/杀软拦截。
> 本机现状（已实测）：**没有 signtool**（未装 Windows SDK），有 `certutil`、PowerShell 5.1。因此下面的自签名路径用 PowerShell 完成；正规证书路径再装 Windows SDK 用 `signtool`。

---

## 一、先搞清楚三种签名

| 类型 | 证书来源 | 成本 | 效果 | 适合 |
|---|---|---|---|---|
| **自签名** | 自己生成（`New-SelfSignedCertificate`） | 免费 | 签名有效，但**未受信任**：用户机器仍弹"未知发布者"，需手动把根证书装进"受信任的根证书颁发机构"才消警告 | 单位内部/自己电脑/测试 |
| **OV 代码签名证书** | DigiCert / Sectigo / GlobalSign / 沃通 / CFCA 等 CA | 约 ¥1000–3000/年 | 受信任发布者；SmartScreen 需一定下载量积累信誉 | 对外分发给客户 |
| **EV 代码签名证书** | 同上（EV 版） | 约 ¥3000–6000/年 | **立即获得 SmartScreen 信誉**；私钥必须在硬件 Token/HSM 里 | 正式对外发布 |
| **云签名（Azure Trusted Signing / DigiCert KeyLocker）** | 微软/CA 云服务 | 按量或订阅 | 私钥在云端，CI 可签，无需插 Token | 有 CI、想省硬件 |

> 2023 年起 CA 新规：代码签名**私钥必须存放在硬件**（USB Token / HSM / 云），不能像以前那样导出 `.pfx` 随便拷贝。买证书时问清"是否提供 Token/云签名"。

## 二、路径 A：自签名（免费，现在就能做）

适合内部使用：给同事装一次根证书以后就不再弹窗。

```powershell
# 1) 生成代码签名证书（当前用户，3 年，仅用于代码签名）
$cert = New-SelfSignedCertificate `
  -Type CodeSigningCert `
  -Subject "CN=XXX单位 表格工具" `
  -KeyUsage DigitalSignature `
  -KeyAlgorithm RSA -KeyLength 2048 `
  -NotAfter (Get-Date).AddYears(3) `
  -CertStoreLocation Cert:\CurrentUser\My

# 2) 导出 pfx（给签名脚本用）和 cer（给用户装根证书用）
$pwd = ConvertTo-SecureString -String "你的保护密码" -Force -AsPlainText
Export-PfxCertificate -Cert $cert -FilePath .\codesign.pfx -Password $pwd
Export-Certificate  -Cert $cert -FilePath .\codesign.cer

# 3) 把证书装进"受信任的根证书颁发机构"（仅本机信任它）
Import-Certificate -FilePath .\codesign.cer -CertStoreLocation Cert:\CurrentUser\Root

# 4) 签名（PowerShell 方式，无需 signtool）
Set-AuthenticodeSignature -FilePath ".\dist\表格工具\表格工具.exe" `
  -Certificate $cert `
  -TimestampServer "http://timestamp.digicert.com" -HashAlgorithm SHA256

# 5) 验证
Get-AuthenticodeSignature ".\dist\表格工具\表格工具.exe" | Format-List Status,StatusMessage,SignerCertificate
```

要点：
- 用户机器上要**先装 `codesign.cer` 到"受信任的根证书颁发机构"**（双击 cer → 安装证书 → 本地计算机 → 受信任的根证书颁发机构），否则仍是"未知发布者"。
- 自签名证书**过期后签名失效**，重新签即可。
- 时间戳服务器（`timestamp.digicert.com` / `timestamp.sectigo.com`）保证证书过期后旧签名仍有效。

## 三、路径 B：正规 OV/EV 证书（对外发布）

### 1. 申请流程

1. 选 CA（DigiCert、Sectigo、GlobalSign、沃通 WoSign、CFCA 等），选 **Code Signing OV** 或 **EV**；
2. 提交主体资料：企业营业执照/个体工商户执照 + 法人身份证明 + 电话核验；个人开发者部分 CA 也支持（价格更高、审核更严）；
3. 通过审核后：OV 通常寄 **USB Token**（或提供云签名账号）；EV 必须 Token/HSM；
4. 安装 Token 驱动，把证书导入到签名电脑的证书存储。

### 2. 用 signtool 签名（需装 Windows SDK）

```bat
:: 按证书指纹签（Token 里的证书）
signtool sign /sha1 <证书指纹> /tr http://timestamp.digicert.com /td sha256 /fd sha256 "dist\表格工具\表格工具.exe"

:: 按 pfx 签（如果你的证书允许导出）
signtool sign /f codesign.pfx /p 密码 /tr http://timestamp.digicert.com /td sha256 /fd sha256 "dist\表格工具\表格工具.exe"

:: 验证
signtool verify /pa /v "dist\表格工具\表格工具.exe"
```

### 3. 云签名（KeyLocker / Azure Trusted Signing）

- DigiCert KeyLocker：装 KeyLocker 客户端 + 用 signtool 的 `/dlib` 参数走云签名；
- Azure Trusted Signing：Azure 订阅（个人/企业需身份验证）→ 创建账号/证书配置文件 → 用 `Trusted Signing` 的 signtool 插件签；
- 好处：私钥不落地，适合自动化；按签名次数或订阅计费。

## 四、签哪些文件、zip 怎么办

| 对象 | 能否签名 | 做法 |
|---|---|---|
| `表格工具.exe`、以后的 `Setup.exe`/`.msi` | ✅ 可以 | 用上面命令签 |
| **绿色版 `.zip`** | ❌ 不能（Authenticode 只对 PE 文件生效） | 先签包内 exe，再压缩；另附 `SHA256SUMS.txt` 供用户校验 |
| `runtime\python.exe` 等第三方程序 | 不建议重签（会破坏原签名） | 保持原样；杀软拦截时加信任 |

生成校验文件：

```powershell
Get-FileHash "dist\表格工具_v1.0_win64.zip" -Algorithm SHA256 | Format-List
# 把结果写进压缩包旁的 SHA256SUMS.txt，用户解压前可比对
```

## 五、本项目建议

1. **单位内部用**：自签名即可（一次根证书安装，之后无警告）；或干脆不签，把程序目录加入杀软信任区。
2. **对外发给其他单位**：买 **OV 证书**，签 `表格工具.exe`；若要立刻消除 SmartScreen 拦截，直接上 **EV**。
3. **只是想少弹几次提示**：先做自签名 + 在说明里写清"首次安装根证书"的步骤，成本最低。
4. 签名和打包的关系：`scripts/build_exe.py` 生成绿色版后，再对 `dist\表格工具\表格工具.exe` 签名，**最后**再打 zip（否则 zip 内 exe 还是未签名的）。

## 六、常见坑

| 现象 | 原因/处理 |
|---|---|
| 签完还是"未知发布者" | 自签名没把根证书装进用户机器的"受信任的根证书颁发机构" |
| `signtool` 找不到 | 没装 Windows SDK；装 SDK 后 signtool 在 `C:\Program Files (x86)\Windows Kits\10\bin\<版本>\x64\` |
| 签名报"私钥不可用" | OV/EV 证书在 USB Token 里，插好 Token 并装驱动；云签名要登录 |
| 证书过期后签名无效 | 签名时加时间戳（`/tr` + `/td sha256`） |
| 杀软仍报毒 | 签名不保证过杀软；需向厂商提交误报、加白名单；少用 `--onefile` 自解压类打包 |
| SmartScreen 仍拦 | 新证书需要信誉积累；EV 或 Azure Trusted Signing 更快 |

## 七、已落地：一键自签名脚本（本机已执行成功）

脚本：**`scripts\sign_exe.ps1`**（UTF-8 BOM 编码，Windows PowerShell 5.1 可跑）。

```bat
:: 在项目根目录执行
powershell -ExecutionPolicy Bypass -File scripts\sign_exe.ps1

:: 换名字/换证书主体
powershell -ExecutionPolicy Bypass -File scripts\sign_exe.ps1 -Subject "CN=XX单位 表格工具"

:: 只签名、不做本机信任、不重打包
powershell -ExecutionPolicy Bypass -File scripts\sign_exe.ps1 -NoTrust -NoRezip
```

脚本依次做：生成/复用自签名证书 → 导出 `dist\codesign.pfx` + `dist\codesign.cer` → 把 cer 加入**当前用户**「受信任的根证书颁发机构」→ 用 SHA256 给 `dist\表格工具\表格工具.exe` 签名（时间戳服务器不通时自动降级为无时间戳）→ 校验 → 重新打 zip → 生成 `dist\SHA256SUMS.txt`。

**本机实测结果（2026-11-09）**：

| 项 | 结果 |
|---|---|
| 证书 | `CN=杨子江 by DeepSeek HARNESS`（文件属性里"发布人"即显示这个名称），指纹 `403028D9500EFEA6018F4051930DBF203C36DC91`，有效期至 2029-11-09 |
| 签名状态 | `Valid`（`Get-AuthenticodeSignature`：签名已通过验证） |
| 签名对象 | `表格工具.exe` 已 Authenticode 签名（发布人 `CN=杨子江 by DeepSeek HARNESS`）；安装包 `.exe` **不做 Authenticode 签名**（实测签名后安装会失败），但其文件属性"发布人"通过版本信息写入 `杨子江 by DeepSeek HARNESS`，且内置的程序本体是已签名版本 |
| 包内 exe | 与已签名 exe 哈希一致（`11d85015…`），说明发的 zip 里就是签名版 |
| 签名后运行 | `--selftest` 退出码 0、`PASS http://127.0.0.1:8765/` |
| 分发校验 | `dist\SHA256SUMS.txt` 同时给出 exe 与 zip 的 SHA256 |

**发给其他电脑时**（关键）：

1. 把 `表格工具_v1.0_win64.zip` + `codesign.cer` 一起发过去；
2. 对方**先装证书**：双击 `codesign.cer` → 安装证书 → **本地计算机** → 「受信任的根证书颁发机构」→ 完成；
3. 再解压运行，就不会再显示"未知发布者"。
   （不装证书也能用，只是首次运行仍会提示未知发布者。）

**注意**：

- `dist\codesign.pfx` 是**私钥**（口令默认 `TableTool@2026`），**不要外发**、不要进版本库；换口令用 `-Password` 参数重跑。
- 重新打包会覆盖签名：**正确顺序是先 `python scripts\build_exe.py` 再 `scripts\sign_exe.ps1`**。
- 不想再信任时：`certutil -user -delstore Root 403028D9500EFEA6018F4051930DBF203C36DC91`。
- 安装包会把证书导入「受信任的根证书颁发机构 + 受信任的发布者」，装完后在文件属性→数字签名里看到的**发布人 = 杨子江 by DeepSeek HARNESS**。
- 自签名只解决"发布者显示"，**不能消除 SmartScreen 拦截**；对外正式发布仍建议买 OV/EV。
